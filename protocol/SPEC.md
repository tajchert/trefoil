# Trefoil direct T3 wire contract

Pinned reference: T3 Code `46449b5379a0089f4ef3ce85bce10a1d28beb4cb`.
Sources: `packages/contracts/src/{environment,environmentHttp,auth,orchestrationV2,server,providerPolicy,modelSelection}.ts`, `packages/shared/src/remote.ts`, `apps/server/src/ws.ts`, installed Effect 4.1.2 `src/rpc/{RpcMessage,RpcSerialization}.ts`.

1. Parse a direct pairing URL's fragment/query `token` (or `t3code:` wrapper `pairingUrl`). HTTPS is the default. Literal RFC1918 private IPv4 HTTP origins require explicit per-environment `allowInsecureHttp` consent; public HTTP and private-looking DNS hosts are rejected. Explicit loopback development URLs may use HTTP (`localhost`, `127.0.0.1`, `::1`); the emulator host address `10.0.2.2` requires the private-LAN consent like other RFC1918 addresses. No redirects are followed; bootstrap and bearer credentials cannot cross origins.
2. GET `/.well-known/t3/environment`, require `orchestrationProtocolVersion: 2`, retain `environmentId`.
3. POST form `/oauth/token`: `grant_type=urn:ietf:params:oauth:grant-type:token-exchange`, `subject_token=<bootstrap>`, `subject_token_type=urn:t3:params:oauth:token-type:environment-bootstrap`, `requested_token_type=urn:ietf:params:oauth:token-type:access_token`, mobile client metadata. Save only issued Bearer access token.
4. Each connect checks descriptor identity and authenticated `/api/auth/session` using bearer. Effective permissions (falling back to legacy scopes only when absent) control `orchestration:operate` writes.
5. POST `/api/auth/websocket-ticket/rpc` with bearer, falling back to `/api/auth/websocket-ticket` **only for HTTP 404**. Upgrade `/ws?wsTicket=<ticket>&orchestrationProtocol=2`. Do not send bearer in the WebSocket URL.
6. Effect JSON Request: `{ "_tag":"Request", "id":"1", "tag":"orchestration.subscribeShell", "payload":{"requestCompletionMarker":true}, "headers":[] }`. This is not JSON-RPC 2.0. JSON object or array frames are accepted. Chunk values receive Ack keyed by `requestId`; terminal Exit carries Success/value or Failure/cause. Cancel streams with Interrupt. Ping every 15 seconds, expire missing Pong after 45 seconds.
7. Request full shell and thread snapshots without optional compact/bounded/deduped encodings. Shell updates merge by ID and remove explicitly. Selected-thread snapshots project messages, runs, activity and pending runtime requests. Domain events invalidate writes and trigger a conflated authoritative `getThreadProjection` read (at most one in-flight and one queued refresh). Subscription completion markers gate writes. Reconnect discards old subscriptions and reads fresh state; old generations cannot apply callbacks.
8. Mutations carry a `commandId` and are sent once; a timeout, disconnect, invalid result or an Exit whose cause only reports `Interrupt` is an uncertain outcome that fails the session (writes disabled) and is reconciled from server state, never replayed. Any other failed Exit (a typed `Fail`, e.g. `OrchestrationV2DispatchCommandError`/`OrchestrationV2ThreadLaunchError`, or a `Die` payload-decode defect) is a definite rejection: the session stays connected and the user sees "T3 rejected the <subject>". Effect encodes the cause as an array of reasons; a single reason object is tolerated. `message.dispatch` has a UUID `commandId` and `messageId`, text, empty attachments, and `dispatchMode.type` `queue_after_active` while the selected thread has an active run or its run/shell status is `preparing`/`starting` (like T3 mobile; the server queues behind an active run either way), else `start_immediately`; it also carries the required creation provenance `createdBy: "user"` and `creationSource: "mobile"` (T3 `OrchestrationV2CreationFields`; without them the server rejects the payload). Interrupt uses `run.interrupt` with active `runId`. Approval/user input uses `runtime-request.respond`; unknown/non-live request capabilities stay visible with response disabled. A new conversation is a local draft (project, server-provided model, runtime mode, default `approval-required`) that allocates a UUID `threadId` and `commandId` once and keeps them until the thread is known to exist. Its first message creates the thread like T3 web: `orchestration.launchThread` with the draft `commandId` and `threadId`, `creationSource: "mobile"`, `projectId`, `title` = T3 title seed of the message (whitespace-collapsed, at most 50 code points plus `...`, fallback `New thread`), `generateTitle: true`, `modelSelection {instanceId, model}`, the draft `runtimeMode` (refused locally when the model's provider lists `supportedRuntimeModes` without it), interaction `default`, workspace `{type: "root"}` and `initialMessage {messageId, text, attachments: []}` where `messageId` is the name-based UUID of `"<commandId>:initial-message"`, so a resend is stable. The result `{threadId, projection, resumed, sequence?}` is validated (`threadId` and `projection.thread.id` equal the draft `threadId`; otherwise uncertain) and its projection seeds the thread before it is selected. After an uncertain or rejected launch the draft and its ids stay (also across reconnect and pause/resume of the same environment); once the session is connected and the shell lists the draft `threadId`, the draft is cleared and that thread opened. Only an explicit user resend repeats `launchThread`, with the same ids: the server deduplicates by `commandId` (`resumed: true`, original title/mode/model kept; a different `threadId` under a used `commandId` is a conflict), and a launch rejected before creation (e.g. missing project) may be resent with its ids. Verified against an isolated T3 by `scripts/validate-t3-wire.mjs`. Selected-thread settings use `thread.runtime-mode.set {runtimeMode}` and `thread.model-selection.set {modelSelection {instanceId, model, options?}}`: the model must be in the server catalog; the thread's current `options` (e.g. reasoning effort) are sent only when instance and model are unchanged. A thread whose provider cannot hand off (T3 `threadSupportsProviderHandoff`: an attached session's `capabilities.sessions.supportsProviderSwitchingViaHandoff`, else an active run locks, a never-run or `v1_import` thread is free, and a finished one is free only while its native provider thread exists) refuses a change to another provider instance locally; the client exposes this as `selectedProviderLocked`. Current values are read from `projection.thread.runtimeMode` and `projection.thread.modelSelection`, the latter mapped to the matching catalog model. `server.getConfig` `settings.defaultRuntimeMode` (default `full-access`) and each provider's `supportedRuntimeModes` (provider-level, forward compatible: unknown literals skipped; absent means unrestricted) are parsed into `ClientState.defaultRuntimeMode` and `ModelOption.supportedRuntimeModes`.
9. Every request has a timeout; pending RPC count is bounded at 64. A lost/timeout/uncertain mutation disables writes until reconnect; a definite rejection does not. No mutation replay occurs. The next authoritative snapshot reconciles visible state; there is no automatic receipt retry.

## Current limits

The client requests complete shell history (`omitIdleSubagents: false` and `omitOlderSettled: false`), so `getOlderSettledThreads` is not needed for this full-snapshot path. No bounded-history pagination UI exists yet. Domain event resnapshotting trades bandwidth for completeness; native incremental reducers can replace this later. Provider approval option restrictions are checked at dispatch; the shared UI currently exposes basic accept/decline. Unsupported requests explicitly direct users to another T3 client. Auto reconnect/backoff, access-token renewal, command receipt lookup, steer, general thread.stop, attachment uploads and terminal streams are follow-up work. Explicit reconnect and [file downloads](FILES.md) are implemented.

Fixtures are synthetic examples shaped from the pinned contracts and contain no user data. The isolated server wire probe lives in `scripts/validate-t3-wire.mjs` and never touches a developer's T3 state.

## Subagents

The selected thread projection's `subagents[]` (`OrchestrationV2Subagent`) is parsed into client state on every projection refetch, which covers `subagent.updated` events. The Agents sheet lists this turn's agents; opening a row selects the child thread. Provider-native children (`creationSource: "provider"`) are read-only.

Stop is offered only while writable, for app-owned agents and Claude-native agents with a strong native ref. Each command is sent once and never replayed. Provider-native and app-owned agents send `subagent.stop {runId, subagentId}` on the parent. For an app-owned agent, the child is then stopped with `thread.stop` only when the server advertises `environment.capabilities.threadStop`; otherwise `run.interrupt {runId, holdQueue: true}` goes to the child's active run. Older servers may reject `subagent.stop`; after that definite rejection the child is still stopped.

## SSH transport (0.2.0 source)

SSH is a transport wrapper around the same V2 HTTP/Effect RPC protocol. Native
SSHJ verifies the host key before password/private-key authentication. First use
requires a user-confirmed SHA-256 pin; a changed pin blocks authentication.

Read the selected T3 home's `userdata/server-runtime.json`, verify live PID and
runtime metadata, and forward an ephemeral **127.0.0.1** listener only to the
remote **127.0.0.1** T3 port. Probe the descriptor and require V2, matching
server/CLI version and the expected saved environment identity. The running
server's matching CLI executes `auth pairing create --base-dir <home> --json`;
its `credential` is exchanged through the tunnel using the existing OAuth flow.
Never log raw command output or replay pairing creation after an unknown result.
No installation, update, service change or remote process stop occurs.

SSH profiles, host pins, access tokens and explicitly saved login secrets live
in Android Keystore-encrypted local files. The local forwarded URL is transient:
it is never persisted as an environment's durable endpoint. Reconnect opens a
new SSH tunnel before reusing the saved T3 token. Background/disconnect closes
the local tunnel; remote agents continue running. An unsaved login is requested
again when a new SSH connection is needed.

## Connection setup corrections (0.2.1 source)

A transient attempt state reports testing stages, host-trust pauses, safe failures and success to retained forms. Entered secrets stay in memory only, never Android saved state. Forms close only after success or cancellation. Public-key content is rejected before SSH, hostname/username edges are trimmed, and errors scroll into view. SSH command errors may report a numeric exit code, but raw stdout/stderr is not shown because it can contain credentials.

Android cleartext configuration permits dynamic private-IP requests; the shared URL policy is the enforcement point, checking literal RFC1918 addresses and stored consent before requests. Redirects remain disabled. Both pairing and reconnect honor the consent flag; old saved environments default to false. Connection cancellation cleans the matching socket generation, and internal timeouts become actionable failures.
